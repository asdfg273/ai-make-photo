1. 文档目的与适用范围
--------------------------------------------------------------------------------

1.1 目的
    本文档描述「当前 UI 的真实结构」：窗口 → 页面 → 面板 → 分组，
    以及被机器校验的控件/方法命名契约。它服务于一次**外观与布局重构**
    （换配色、换布局、换控件排布），目标是让重构者在不破坏功能的前提下改视觉。

1.2 适用范围
    - 覆盖: 工作目录下 ui/ 全部 Python 文件，以及主窗口 main.py、
      utils/app_events.py、utils/app_generation.py 中与 UI 直接相关的部分。
    - 不覆盖: 生成管线内部算法、模型加载、workflow 引擎语义、nodes/ 目录。
    - 全部结论基于**本次审计时刻**的源码。审计时未加载任何模型
      （只用 QT_QPA_PLATFORM=offscreen 离屏构造外壳），因此凡是需要真实推理
      才能观察到的现象，本文档一律标注 （未验证）。

1.3 审计方法与可信度
    - 行号、数量、属性名均来自源码实测（脚本统计，见第 2 节的计数说明）。
    - 结构类结论（页面数、栈成员、信号连接是否成功、菜单项、快捷键）
      通过离屏构造 ShellMixin 迷你宿主实测得到，属于"真实结构"，非推测。
    - 涉及运行期观感的结论（例如"控件叠加"）以源码注释与修复痕迹为依据，
      并标注为历史缺陷/已修。

4.4 自检与降级的确切行为（contracts.py:99-138）

    install_aliases(host)   :99-107
        逐个别名 setattr；目标不存在只记 warning，不抛异常。
        LIST_ALIASES 无条件安装成 list（缺失项为 None）：contracts.py:106-107。

    check_contract(host)   :110-125  → 返回 (critical_missing, minor_missing)
        1) 遍历 GLOBAL_WIDGETS + PAGE_WIDGETS 全部控件名（:112）；
           判定标准是 `hasattr(host, 名字) and getattr(...) is not None`（:115）；
           不在 CRITICAL 里的缺失归入 minor（:117）。
        2) METHOD_CONTRACT 里每个名字用 `callable(getattr(host, name, None))`
           判定，缺失**一律计入 critical**（:118-121）。
        3) 别名若指向的对象与真名不是同一实例 → 记成 minor "alias:xxx"（:122-124）。

    apply_degradation(host, critical_missing)   :128-138
        - 记录 logger.error；
        - 把 btn_generate 与 btn_gen_video **置灰并写 tooltip**
          "⚠️ 关键组件缺失: ..."（:134-138）。
        - 也就是说：重命名/漏建关键控件不会崩，而是"生成按钮永久点不动"，
          这是最容易被误判成"功能坏了"的失败模式。

5.9 关于 _wire：为什么存在（ui/core_panel.py:20-26）

    def _wire(host, signal, method_name: str) -> None:
        """防御性信号连接：宿主缺方法时告警而不是崩溃（页面隔离需要）。"""
        fn = getattr(host, method_name, None)
        if callable(fn):
            signal.connect(fn)
        else:
            logger.warning(f"⚠️ 信号未连接（宿主缺方法）: {method_name}")

    为什么必须有它：页面/分组是在**不知道宿主具体是谁**的前提下构建的。
    tests/test_ui_contract.py 里的 MiniApp 只继承 QMainWindow + ShellMixin，
    没有 EventMixin/GenerationMixin/VideoPanelMixin，所以
    start_generation / select_image / on_generate_video 等 50+ 个业务方法都不存在。
    本次离屏审计实测：用 MiniApp 构造外壳时，_wire 打印了 **54 条**
    "信号未连接（宿主缺方法）"告警，但 **setup_ui 依然成功、契约 critical 为空**。
    如果没有 _wire（改为 host.btn.clicked.connect(host.meth)），
    这些页面会直接 AttributeError 崩在启动路径上 —— 也就是说
    _wire 是"页面可独立构建/可被测试桩驱动"的前提。

    ★重构规则：新写的页面/分组里，凡是连接"宿主方法"的地方都要用 _wire(host, ...)，
      不要写成 host.btn.clicked.connect(host.method)。
    引用位置（共 6 个文件 import 它）:
      ui/shared_groups.py:14、ui/pages/txt2img_page.py:13、ui/pages/img2img_page.py:14、
      ui/pages/video_page.py:18、ui/shell.py:40/:307（只导 build_* 函数）。
    例外（直接 .connect）：三处刻意不用 _wire，因为连接的是**局部** lambda 或
      确定存在的方法：core_panel.py:118-119（局部 lambda 调 show_preset_menu）、
      shell.py:157-168（lambda 包一层判 isEnabled）、
      video_page.py:520（局部 _toggle_rife）、
      img2img_page.py:121-122 / :135 / :167-168（局部 lambda）。

7. 目前 UI 的问题清单
--------------------------------------------------------------------------------

7.1 【历史缺陷·已修】ParamPanel._clear() 只用 deleteLater() 导致切换节点时控件叠加

    症状: 在工作流编辑器里快速切换节点（或连续 show_node）时，面板里出现
          "两个采样器 / 两组参数"叠在一起。
    根因: 只调 deleteLater() 时，控件只是**排队**等待事件循环删除，这期间它仍是
          父控件的可见子控件，会停在原坐标继续绘制。
    证据: ui/workflow_editor/param_panel.py:41-69 的 _clear()，其中 :44-49 的
          注释原文写明了这个陷阱；修法是先 setParent(None) 立即解除父子关系
          （:56-57、:66-67），再 deleteLater()。子布局也要连里面的控件一起摘
          （:60-68），否则 QFormLayout 里的行还会残留。
    影响: 已修，当前行为正确。但它代表的是一类通用陷阱 ——
          **任何"清空后重建"的面板都必须先 setParent(None)**。
    建议: 把这套清空逻辑抽成一个公共工具函数（例如
          ui/components/clear_layout.py: clear_layout(layout)），
          让以后所有"动态重建"的面板复用。目前项目里只有这一份正确实现，
          其他地方若将来引入清空重建很容易再犯。
    同类风险点（可用同一工具统一）: QStackedWidget 页面/参数区切换、
          shared_groups 若将来支持动态重排、画廊列表若是重建而非清空。

7.7 【中等·_wire 造成的静默失效】连不上的信号只打 warning，按钮可能永久无效

    症状: 控件创建了、也显示了，但点击毫无反应；日志里只有一行
          "⚠️ 信号未连接（宿主缺方法）: xxx"。
    证据: ui/core_panel.py:20-26；本次离屏审计用 MiniApp（只有 ShellMixin）实测
          打印了 54 条此类告警（例如 start_generation、stop_generation、
          select_image、on_generate_video、_on_video_mode_changed…）。
          在**真实** app 里，这些方法由 EventMixin/GenerationMixin/VideoPanelMixin
          提供，不会缺；但如果重构中把某个页面从 shell 的构建链里挪走、
          或改了 mixin 继承，就会退化成"按钮能点但没反应"。
    影响: 最难排查的一类 bug（无异常、无弹窗）。
    建议: (1) 保留 _wire 的写法；(2) 重构后**务必看启动日志**，正常启动时
              不应出现任何"信号未连接"告警
              （真实启动可能出现少数，例如 audio_output 相关的 minor 项，
               但"宿主缺方法"的 warning 应当为零）；
          (3) 建议以后把 warning 升格为可选的严格模式（环境变量控制），
              在 CI/自检里跑一次"零告警"断言。

7.8 【中等·布局靠"补丁式"尺寸策略维持】400px 面板与长文本控件的对抗

    症状（历史）: 长度很长的下拉框/复选框会把 400px 宽的参数面板撑爆，
                 右侧控件被整体裁掉，看起来"控件少了"。
    根因与现有补丁（都在注释里写明）:
      - params_panel.setFixedWidth(400)                          shell.py:288
      - params_scroll 水平滚动条永久关闭 + setWidgetResizable   shell.py:294-297
      - core_wrap / params_stack / shared_wrap 三处都强制
        SizePolicy.Horizontal = Ignored                          shell.py:310-312 / :316-318 / :326-328
      - 每个页面 params_widget 也被强制 Ignored                   shell.py:91-93
      - combo_model / combo_model_type / combo_ai_model /
        combo_enhance_mode / combo_trans_mode 各自 setMinimumContentsLength
        （core_panel.py:38-40、:60-62、:179-181、:203-205、:222-224）
      - params_stack 用 setMinimumHeight(max(sizeHint, 80)) 撑高，
        滚动交给外层（shell.py:202）
      - NavRail 固定宽 64（nav.py:12）
    影响: 这套"到处 Ignored"的策略是**为了让布局不溢出而加的多点补丁**，
          彼此耦合：改动任一处宽度/滚动策略都可能让长文本控件再次溢出或
          让面板出现空白滚动条。重构布局时这是最容易踩的地方。
    建议: 重构时把"面板宽度、滚动区边界、Ignored 策略"当成一个整体重新设计
          （例如用 QFormLayout 的 FieldGrowthPolicy + 明确的 minimumWidth），
          而不是在现有补丁上再叠一层；改完必须实测"最长模型名/最长 LoRA 名"
          时的显示效果（这需要真实模型目录 → （未验证，本次未跑真实 GUI））。

8.1 建议（按优先级，1-4 是"做美术重构前后各一次"的动作）

    (1) 先冻结接口，再动视觉。

    (3) 建立单一设计令牌源。

        muted/surface/card/border），把 QSS 全部改成引用令牌值（Python f-string 拼接），

        ui/widgets.py 的 8 处、ui/components/collapsible.py 的 1 处开始，
        因为这几个是"当前默认 UI"实际用到的）。

                   证据: ui/components/collapsible.py:7-43。
                   ⚠ 它现在的标题按钮样式是**内联硬编码** "#22303d"（:21-23），
                     与 theme.APP_QSS 里给 QWidget#collapsibleHeader 的规则重复但
                     没有真正用上（该 objectName 从未被设置）→ 改主题时必须一起处理。
    (5) 保留全部 QSS 钩子（objectName/property 清单见 4.7），并在重构后做一次
        "启动日志零告警"的检查（7.7）。

    A. 重命名任何控件属性名
