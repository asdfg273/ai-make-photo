# 角色一致性增强设计

日期：2026-10-28

## 目标与范围

在现有角色卡、场景批量和生成链路上增加四项能力：

1. 角色卡保存 2–4 张带姿势标签的参考图，兼容旧 `ref_image_path`。
2. 批量生成后校验脸部相似度，低分图片按有限次数自动重 roll。
3. 持久化并复用现有 `extracted_features` 提示词视觉特征缓存。
4. 应用角色及生成时自动注入所选 LoRA 的触发词。

不重写采样器，不把参考图张量序列化到 JSON，不引入无限重试，不在模型不可用时伪造人脸相似度结果。

## 方案比较

### 多参考图

- 采用：角色卡新增 `reference_images: [{path, pose}]`，首图同步旧字段；批量逐张选择单图注入现有 IP-Adapter。改动集中，兼容现有生成链。
- 不采用：一次把 2–4 张全部送入多 IP-Adapter。会混合姿势且显著增加显存，不符合按姿势切换目标。
- 不采用：另建角色参考图数据库。当前规模没有必要。

### 人脸校验

- 采用：独立 `FaceConsistencyChecker`，懒加载 InsightFace；以生成图与角色全部有效参考图的最大余弦相似度判定。批量每张最多重试角色配置的次数。
- 不采用：OpenCV 直方图或像素差冒充人脸识别。它无法可靠表达身份一致性。
- 不采用：低分无限重 roll。可能持续消耗算力且无法收敛。

### 特征缓存

- 采用：保存角色时通过现有 `_gt_extract_character_features` 预提取提示词特征；JSON 保存参考图签名和文本，生成时签名匹配直接复用。
- 不采用：把 Qwen 特征称为 CLIP 张量缓存或持久化 IP-Adapter image embeds。现有字段与消费链是提示词文本，张量缓存属于另一项架构工作。

### LoRA 触发词

- 采用：统一解析下拉框 `name[trigger]` 与同目录/既有 `loras` 目录 `.txt` 旁文件；在生成上下文合并，应用角色时同步可见提示词，按完整词组去重。
- 不采用：只修改手动按钮，或每次重复前插导致提示词膨胀。

## 数据结构

`Character` 新增：

- `reference_images: List[dict]`，每项为 `{"path": str, "pose": "front|side|full"}`。
- `face_check_enabled: bool = True`。
- `face_similarity_threshold: float = 0.55`。
- `face_max_retries: int = 1`。

`extracted_features` 使用可序列化结构：

```json
{
  "version": 1,
  "refs": {
    "front": {"path": "...", "mtime_ns": 0, "size": 0, "text": "..."}
  }
}
```

旧角色加载时，若只有 `ref_image_path`，规范化为一张 `front` 参考图；旧 `extracted_features=None` 保持有效。任何参考图内容变化都会使对应缓存失效，不影响其它参考图缓存。

## 多参考图界面与选择规则

角色编辑器允许一次选择 2–4 张图片，也允许保留单图旧工作流；列表展示文件名和姿势。默认按选择顺序分配正面、侧面、全身，第四张标记为备用 `extra`，选择超过 4 张时忽略并提示。提供姿势切换和移除操作，主预览跟随当前项。

批量选择优先级：

1. 场景 `pose_prompt` 包含 `side/profile/侧面` → `side`。
2. 包含 `full body/full-body/全身` → `full`。
3. 包含 `front/正面` → `front`。
4. 无匹配时按任务序号在有效图片间轮转，避免整批固定同一姿态参考。

每次 `_push_params` 同时更新 shell 的 `ipa_image_path`、参考图状态与 `_active_character`，确保后续特征缓存读取的是本批角色和本张参考图。

## 人脸校验与重 roll

`FaceConsistencyChecker` 只负责：

- 懒加载本地/可获取的 InsightFace `buffalo_l` 模型。
- 提取每张图最大人脸的归一化 embedding。
- 返回生成图对所有参考图的最大余弦相似度；任一无脸时返回明确状态。

批量收图后、标记 `done` 前执行校验：

- 分数达到阈值：正常完成，并记录分数日志。
- 低于阈值且剩余重试：不把本次图片加入成功输出，不增加任务序号，换种子重新生成同一 `_Job`；清单记录 `retrying` 和最近分数。
- 达到重试上限仍低分：任务标记 `failed`，保留候选图路径用于结果页诊断，错误写明最终分数。
- 依赖/模型不可用或未检测到人脸：不自动重试，标记 `failed`，错误说明“未校验”原因，避免将无效结果算作通过。

默认一次重试；阈值夹在 0–1，重试次数夹在 0–3。测试注入 fake checker，不下载人脸模型。

## 特征缓存流程

- 角色页保存：若 shell 提供特征提取器，对所有有效参考图预提取；单张失败不阻断角色保存，保留其它有效缓存。
- 应用角色/批量：把当前角色与角色库关联到 shell。
- 生成准备：先查角色持久缓存；签名命中直接返回文本，未命中再走现有内存缓存和 AI 提取，并回填角色缓存。
- 不自动在保存时加载 IP-Adapter CLIP 模型，不保存大张量。

## LoRA 触发词流程

新增无副作用工具函数，负责解析展示名、读取触发词、去重合并。

- `name[trigger]` 的方括号内容优先作为触发词。
- 若无内联触发词，按现有顺序读取 `.txt` 旁文件。
- 应用角色 LoRA 成功后立即合并到可见提示词。
- 每次生成前根据当前所有选中槽位再合并一次，覆盖手动选择 LoRA 的场景。
- 已完整出现的触发词不重复添加；生成不反复修改 UI 原文，避免提示词逐次膨胀。

## 错误处理与兼容性

- 旧角色 JSON 缺少新字段时采用默认值；未知姿势回退 `front`。
- 缺失图片在选择参考图时跳过并记录日志。
- 人脸功能失败只影响当前任务，不中止后续场景。
- 特征提取失败不阻止生成，退回原提示词。
- LoRA 触发词读取失败不阻止生成，记录警告。

## 测试与验收

- 角色卡旧格式迁移、2–4 张规范化、导出导入、缓存签名失效。
- 批量姿势匹配与轮转、同一张低分重试、达到阈值成功、超限失败、无脸不重试。
- 持久特征命中时不调用提取器，未命中才提取。
- 内联/旁文件触发词、自动注入、重复调用不重复。
- Qt 离屏验证多图编辑控件；全部模型相关测试使用 fake。
- 从最终提交导出干净快照，运行新增测试及角色场景、批量、生成/UI 相关回归。

非目标：本轮不执行真实 InsightFace 下载、真实 CLIP/Qwen 推理或人工批量出图；这些由用户统一测试。
