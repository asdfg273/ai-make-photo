# 推理性能与素材管理增强设计

日期：2026-10-29

## 目标与边界

本轮覆盖五项相互独立但共用生成链路的增强：Flux/SD3 量化与分块 offload、TeaCache 风格步间缓存、FIFO 生成队列、模型示例图预览、画廊全文与 CLIP 相似检索。

不承诺未经实测的显存数值或加速比例。量化、NVFP4、CLIP 和真实模型生成均按本机能力运行；缺依赖、缺本地模型或后端不支持时给出明确错误，不伪装成功，不静默下载大模型。`models/_pending_dit/` 当前为空，因此真实 DiT 权重验收留待用户提供模型后进行。

## 方案比较

1. **可选原生后端 + 独立适配模块（采用）**：量化使用 diffusers 已安装的 TorchAO / NVIDIA ModelOpt 配置，分块卸载使用 `apply_group_offloading`；缓存、队列和搜索均为独立模块。优点是不复制第三方实现、可测试、可明确回退，代价是不同后端能力需要运行时检测。
2. 自写张量量化与采样器：可控但工作量、数值风险和回归范围过大，不适合本轮。
3. 仅增加 UI 设置：改动小但会形成空开关，不采用。

## 1. DiT 量化与分块 offload

新增 `core/dit_optimization.py`，负责：

- `off` / `fp8` / `nvfp4` 配置解析；FP8 优先 TorchAO 权重量化，不可用时明确报告，不偷偷改成其他精度；NVFP4 使用 `NVIDIAModelOptConfig("NVFP4")`。
- 通过 `PipelineQuantizationConfig(quant_mapping={"transformer": ...})` 只量化 DiT 主干，文本编码器和 VAE 保持原策略。
- 对 `pipe.transformer` 应用 block-level group offload，支持每组块数、CUDA stream；应用成功后标记管线，通用 VRAM 策略不再重复安装 model/sequential offload。
- 根据量化档位列出能力要求与权重估算比例，所有后端导入错误包含可操作的依赖提示。

`LoadContext` 增加推理优化配置，`SingleFileLoader` 在 Flux/SD3 加载时应用。模型管理器把优化配置签名纳入“同模型可跳过加载”的判断，修改精度后必须重载。架构列表允许已具备单文件加载链路的 Flux/SD3 进入实际测试，但不把“可选择”描述为“已实测”。

设置页新增“推理性能”页，保存量化、分块 offload、每组块数与步间缓存配置，默认量化关闭，避免改变既有 SDXL 行为。

## 2. TeaCache 风格步间缓存

新增 `utils/step_cache.py`，对 Flux `transformer` 和 SDXL `unet` 的 forward 做可撤销包装：

- 比较相邻步输入张量的相对 L1 距离并累计；低于阈值且未超过连续跳过上限时复用上一步模型输出。
- 每张图、每次重新配置和模型卸载时复位；首步与连续跳过达到上限时强制真实计算。
- 记录计算/复用次数供日志与测试使用。该实现是 TeaCache 风格的通用步间缓存，不冒充某一论文仓库的逐行移植；实际质量和耗时需按模型验收。
- 不修改采样步数，不在 CPU 上复制完整 latent；距离计算使用 detach 后的抽样张量。

## 3. FIFO 生成队列与暂停

新增 `utils/generation_queue.py` 和 `ui/generation_queue_dialog.py`：

- 队列项保存不可变 ID、标签、控件参数快照、模型数据、参考图路径和状态；支持待运行项编辑、置顶、上下移动与移除。
- 主生成按钮把当前参数加入 FIFO；空闲时自动派发，运行期间主窗口保持可交互。角色批量 `_batch_mode` 继续直接调用原生成入口，避免双重排队。
- 暂停在采样步边界协作等待，不销毁当前管线；恢复继续，取消会唤醒等待线程。暂停只冻结生成线程，不阻塞 Qt 主线程。
- 队列对话框提供 prompt、负向词、步数、CFG、种子、数量编辑及暂停/恢复、插队、删除；不提供跨版本不可靠的任务持久化。

## 4. 模型选择器缩略图

新增 `utils/model_previews.py`：按 ComfyUI 惯例查找模型同目录、同主文件名的 `.png/.jpg/.jpeg/.webp`，并支持 `.preview.png` 等变体。扫描器只记录路径，不读图像。

模型下拉项显示小图标，当前模型信息区显示较大预览；没有示例图时使用空状态，不生成虚假封面。示例图命名说明写入项目文档。

## 5. 画廊全文与 CLIP 相似检索

新增 `utils/gallery_search.py`：

- 文本检索把查询拆成多个词项，全部匹配文件名或完整 prompt；保留收藏、时间、媒体和 NSFW 过滤的组合行为。
- CLIP 使用 `transformers` 懒加载，本地模型只从显式配置目录、`models/clip/` 或本机 Hugging Face 缓存读取，`local_files_only=True`，不自动联网下载。
- 图像向量按路径、大小、mtime 缓存到 `data/gallery_clip_index.json`；支持文本搜图和以当前图片查相似图，余弦相似度只负责排序，不伪造绝对匹配概率。
- 编码在后台线程执行，通过 Qt 信号回到画廊；检索期间禁用触发按钮，可一键回到普通过滤。缺少本地 CLIP 时保留现有关键词搜索并提示模型配置方式。

## 错误处理与兼容性

- 新依赖全部延迟导入；SDXL 既有生成默认不启用量化，缓存默认关闭。
- 量化或 group offload 失败不静默换精度；加载失败沿用现有错误信号并保留配置。
- 队列快照只写 Qt 主线程，工作线程不直接访问控件。
- CLIP 索引损坏时重建单条或整个索引，不影响画廊打开和文件操作。

## 测试与验收

新增纯单元和 Qt 契约测试，覆盖：量化配置映射与缺依赖错误、group offload 防重复、缓存命中/上限/复位、FIFO 编辑/插队/暂停唤醒/批量绕过、模型示例图命名、全文过滤、向量缓存与相似排序、UI 控件存在性。

在干净提交快照运行相关测试、既有角色/批量/UI 回归及 `py_compile`。真实 Flux/SD3 权重、FP8/NVFP4 内核、8GB 显存占用、缓存画质与速度、本地 CLIP 模型检索列为用户统一实测项，不用模拟测试替代这些结论。
